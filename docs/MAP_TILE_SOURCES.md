# 地图地名与符号的维护

原有地名来自两份 WWP 和 R88 词典的 `places`。审核过的补充地名、指定缩放的排版以及地图符号在下列文件中维护。

| 文件 | 维护内容 |
| --- | --- |
| `assets/placenames/Cities.wwp`、`Synoptic.wwp` | 作者既有的城市和宏观地名。记录序号从 0 起算。 |
| `dict/placenames/regions.json` | 生成词典 `places` 的原始省州清单，含中文、经纬度和起始缩放。 |
| `dict/placenames/reviewed_map.json` | 额外审核的实体、逐缩放标签、符号与同实体关联。构建后位于 `CMOLocalizer.json` 的 `reviewed_map`。 |
| `dict/placenames/reviewed_map_evidence.json` | 维护者用于复核的原图字框、来源、区域与旧标签身份，以及所引用的 WWP/R88 成员。 |
| `dict/placenames/global_reviews.jsonl` | 11 条独立原图核名记录，涉及加拿大十省，魁北克有两个缩放。保留原 Stamen ID、记录指纹和外交部中文名称出处。每条的 `source_anchor_verified` 均为 `false`，定位另见动态维护证据。 |

## 如何登记

先核对完整的原文字样、行政层级和地理位置。相邻瓦片有时各印出同一地名的一部分，应把两边放在同一缩放的全球像素坐标中拼回。每个原图标签保留原文、缩放、完整半开字框、原图身份和能证明中文的出处。通过同地双语记录核名时，同时核对地物类别和空间位置。同名异地、同地不同缩放、不同地图版本各自留证。只有地点身份能够确认时，记录到待核表，待中文证据取得后再加入显示数据。

作者已有成员可以直接引用 `Cities`、`Synoptic` 或 `Regions`。两份 WWP 取文件中的原序号。省州取最终词典 `places` 数组下标。构建器从 `regions.json` 读取数据，先规整经纬度和起始缩放，再按起始缩放、中文、纬度、经度排序。维护证据的 `members` 行依次保存图层、从零起的序号、正式显示名、纬度和经度，构建时与实际输入的成员相核。

新增实体记录类别、中文和定位坐标。标注的位置可以与地理锚点不同，排版偏移在指定缩放上以像素计。使用逆投影时，在维护证据中写明锚点来自实测节点、原图符号或文字框中心，以便区分地图标字的位置与实测地点。

一个实体可以有多个缩放的标签。每条标签关联实体、缩放、排版偏移、显式分行、字号和字重。沿用实体名称时可省去分行。已有上游成员与新标签经核实为同一地点时，注明成员、缩放与标签的关联。独立同名地点各自保留。任一缩放上，同一个上游成员只能由一条标签承接。

圆点、三角和原图斜杠按该级位置登记。可确定所属文字时链接标签，无名地物符号可独立保留。名下另印的高程可随名称分行，独立高程按高程记录，例如 `5000 m` 对应“5000米”。审核和统计应区分地名、独立高程和符号。

## 如何回查一项修改

1. 从原图印次或已有成员定位。原图的 `Z6-5978-9495-6048-9517` 表示第 6 级全球像素框 `[5978,9495,6048,9517)`，落在 `6/23/37`，原文 Florianópolis，中文为弗洛里亚诺波利斯。楚科奇海则可从 `Synoptic.wwp #306` 查起。
2. 由维护证据核回实体与中文。保留独立原图来源与译名出处。曾参与两个样本队列的同一原图印次共用数据身份。
3. 查对应级别的实际绘制位置及邻片。跨边界字形、描边和符号均可能在多片留下像素。原地名所在片与中文实际覆盖片分别记录。
4. 验证已有 WWP/R88 成员在原可见级别的显示和去重。受影响的标签、符号与跨片位置应在生产引擎的 HTTP 请求和安装器缓存上查看，和源码数据一起复核。

动态排版的 `labels[i]` 与维护证据的 `labels[i]` 对应。证据行前八列依次为历史区域下标、原标签 ID、原文、核定全球字框、原文来源下标、译名来源下标、定位依据、坐标来源下标。末四列为类型、说明下标、补充属性下标和地理核查证据下标。区域查 `regions`，来源查 `sources`，末三项分别查 `notes`、`attributes` 和 `geographic_evidence`。需要查实体时，由运行数据 `labels[i][0]` 指向 `entities`。原 WWP 补绘项的原图字框为空，可按成员及缩放回查。维护证据中保留的区域 ID 描述原始材料的归属。

原图表 `tiles` 每行保存 XYZ、PNG 的 SHA-256、供应商地址前缀的下标。按 `<tile_url_roots 中的前缀>/<z>/<x>/<y>.png` 取核验用原图，下载后先核文件指纹。孟公镇依靠更高一级的完整字样协助识别，此类只作旁证的原图也在表中。实际文字纠错可查 `translation_corrections`，例如六级 Nay Pyi Taw 由“奈比多”订正为“内比都”。

审核后补全某处字框时保留原始审核 ID。例如卓木拉日峰的初始 ID 为 `Z10-196009-109923-196075-109938`，核定框为 `[196009,109923,196075,109955)`，包括同一峰名下方的 7326 米标高。跨版本追溯以初始 ID 和核定字框两列联结，不能用调整后的字框覆盖旧 ID。

## 从仓库重建

在仓库根目录依次运行以下命令。

```sh
python -B scripts/build_dict.py
python -B scripts/test_reviewed_map.py
```

第一条命令从维护源生成 `dict/CMOLocalizer.json`。第二条检查原成员关联和同级归属的边界。字体绘制和缓存路径需要实际运行 .NET Framework 引擎验证，参见[中文地图标签绘制](PLACENAME_LABEL_RENDERING.md)。
